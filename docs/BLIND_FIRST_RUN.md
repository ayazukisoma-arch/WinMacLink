# Mac情報を隠した初回テスト — 2026-11-03

## 方法

`python tools/blind_first_run.py` で再現できます。`--gui` を加えると隔離した初回GUIも開きます。現在の版はWindows用です。

- Pythonソースだけを別フォルダーへコピー。元の `.local/profile.json` はコピーしない。
- テスト子プロセスのLOCALAPPDATA・USERPROFILEを空の専用フォルダーにする。既存アプリ設定・ユーザーSSHフォルダーを使用しない。
- SSHエージェントの環境変数を子プロセスから外す。
- 保存済み接続が読み込まれないこと、既存SSHホームが見えないことを検査。
- 実行を許可する検出コマンドは有線アダプターの読み取りとARP読み取りのみ。SSH実行はテストで拒否。
- 実際の有線ネットワークの発見結果と、ARP履歴を空にした模擬結果を分けて記録。
- 既定と異なるサブネットでも抽出できるかを確認。
- 親プロセスの監査で、元の接続設定の内容が実行前後で変わらないことを確認。監査値は子プロセスへ渡さない。

これはOSのアクセス制御による完全なサンドボックスではなく、アプリ設定・ユーザーパスと実行経路を分離する検証です。既存OSのドライバー、物理ネットワーク、Macの共有設定は残っています。初期状態のOSや鍵未登録のMacを再現したと主張しません。

## 実測結果

| 検査 | 結果 |
|---|---|
| 保存済みプロファイル | 見えない |
| 既存SSHホーム | 見えない・使用しない |
| SSHコマンド実行 | 0回 |
| 実ネットワークからの有線機器候補 | 1台 |
| Macとして認証できた候補 | 0台 |
| 接続履歴が空の場合 | 0台 |
| 既定外のサブネット | 抽出成功 |
| Wi-Fi側機器 | 除外成功 |
| ユーザー名の自動取得 | できない |
| 完全自動で初回接続 | 未達 |
| OS設定変更 | なし |
| 元の接続設定 | 監査で変更なし |

最初の隔離テストを2回実行。初回GUIも表示確認し、ユーザー名が空で、実際のユーザー名・鍵のパス・登録済みの照合名が引き継がれていないことを確認しました。この時点のGUIは鍵の場所など技術的な設定を要求していました。その後、確認ガイド＋ユーザー名・有線IPの2項目へ改修しました。初回の鍵準備・認証完了は依然として未実装です。

## 判明した不足

1. 新しい相手がARP履歴にない場合の発見経路がない。ローカルサービス発見や直結相手検出が必要。
2. 機器候補をMacとして識別・本人確認する初回経路が未実装。既存のホスト鍵で確認する方式は使えない。
3. 初回の認証鍵準備、ホスト鍵照合、Macのユーザー名確認を順序立てて案内する必要がある。
4. 登録画面がSSHのパス・照合名を要求するため、一般利用者向けの導入完了とはいえない。

従って「登録済み環境での成功」を「他のユーザーが初回から自動導入できる」と言い換えません。
